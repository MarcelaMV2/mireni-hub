Las dos versiones buscan el mayor, el menor y el intermedio de tres enteros positivos diferentes, y calculan la diferencia entre los extremos. Cambia la forma de organizar las decisiones, pero los resultados válidos deben coincidir.

## Datos de entrada

| Variable | Tipo | Significado y validación |
| --- | --- | --- |
| `a` | Entero | Primer número: debe ser mayor que cero y distinto de `b` y `c`. |
| `b` | Entero | Segundo número: debe ser mayor que cero y distinto de `a` y `c`. |
| `c` | Entero | Tercer número: debe ser mayor que cero y distinto de `a` y `b`. |

## Datos de salida

| Variable | Tipo | ¿Qué guarda? |
| --- | --- | --- |
| `mayor` | Entero | El valor más grande de los tres. |
| `menor` | Entero | El valor más pequeño de los tres. |
| `intermedio` | Entero | El valor que queda entre el menor y el mayor. |
| `diferencia` | Entero | El resultado de `mayor - menor`. |

Las salidas se calculan; no se piden por teclado. Solo se muestran cuando los tres datos son válidos. Al ser diferentes, hay un único mayor, un único menor y un único intermedio.

## Análisis de resolución

### 1. Validar que todos sean positivos

`a <= 0 O b <= 0 O c <= 0` detecta si **al menos uno** es inválido. Por ejemplo, con `a = 15`, `b = 0`, `c = 20`, la segunda comparación es verdadera y se rechazan los datos.

Se utiliza `O` porque basta un número inválido para rechazar el conjunto. Con `Y` solo se detectaría el caso en que los tres fueran inválidos a la vez.

### 2. Validar que sean diferentes

`a = b O a = c O b = c` compara las tres parejas posibles. Con `a = 15`, `b = 8`, `c = 15`, se cumple `a = c`, así que hay repetición. Comprobar únicamente `a = b` no sería suficiente.

Estas estructuras son selectivas: muestran el rechazo pero no solicitan nuevos números. Ninguna de las versiones utiliza ciclos.

### 3. Qué cambia entre simples y dobles

| Selectivas simples | Selectivas dobles |
| --- | --- |
| `Si … Entonces … FinSi`: ejecuta un bloque solo si la condición es verdadera. | `Si … Entonces … SiNo … FinSi`: elige uno de dos caminos. |
| Las comprobaciones de error son independientes; pueden mostrarse ambos mensajes si fallan ambas reglas. | Primero se valida positividad; solo si pasa se revisan las repeticiones. Se muestra el primer rechazo encontrado. |
| Una condición adicional de datos válidos protege todo el cálculo. | Las ramas `SiNo` dejan el cálculo únicamente en el camino válido. |

### 4. Ajuste necesario en la versión simple

En el pseudocódigo recibido, los dos primeros `Si` muestran mensajes, pero **escribir un error no detiene el algoritmo**. Con números repetidos, algunas variables podrían quedar sin asignar y aun así se intentaría calcular la diferencia o mostrar resultados.

Por eso se agregó un `Si` que contiene las comparaciones, la resta y las salidas, con la condición `a > 0 Y b > 0 Y c > 0 Y a <> b Y a <> c Y b <> c`. Todas las reglas deben cumplirse para entrar. Se mantienen las selectivas simples: **no se añade ningún `SiNo`** a esta versión.

### 5. Encontrar mayor y menor con simples

Para que `a` sea el mayor debe superar a los otros dos: `a > b Y a > c`. Se comprueba lo mismo para `b` y `c`. Como los números son diferentes, exactamente una de las tres condiciones asigna `mayor`.

Para el menor se invierten las comparaciones: `a < b Y a < c`, y de la misma forma para los otros valores. Se utiliza `Y` porque ser mayor o menor que un solo número no basta para ser el extremo del conjunto.

### 6. Encontrar el intermedio con simples

Una vez conocidos los extremos, un valor es intermedio si es **mayor que `menor` y menor que `mayor`**. Por ejemplo, con `menor = 8` y `mayor = 20`, el número `15` cumple ambas condiciones.

### 7. Recorrer los caminos de la versión doble

Para encontrar el mayor, primero se compara `a > b`. Si es verdadero, `b` ya no puede ser el mayor y se compara `a` con `c`. Si es falso, se compara `b` con `c`. Cada camino asigna un valor a `mayor`.

Para el menor se sigue el mismo razonamiento con `<`. Para el intermedio, se pregunta si `a` es distinto de ambos extremos; si no lo es, se prueba `b`; si tampoco lo es, el intermedio debe ser `c`. Esta última deducción funciona porque ya se comprobó que los tres son diferentes.

En la rama de datos repetidos de tu versión doble se conservan `a <- 0`, `b <- 0` y `c <- 0`. **No son necesarias para impedir el cálculo:** lo que lo impide es estar en una rama diferente del `SiNo` que contiene el proceso. Esas asignaciones solo reemplazan los datos y luego termina el algoritmo.

### 8. Prueba de escritorio con `a = 15`, `b = 8`, `c = 20`

| Etapa | Versión simple | Versión doble | Resultado |
| --- | --- | --- | --- |
| Validar | No hay ceros, negativos ni parejas iguales; se entra al bloque válido. | Se recorren las dos ramas `SiNo` de validación. | Datos aceptados. |
| Mayor | Solo `c > a Y c > b` es verdadero. | `a > b` es verdadero; `a > c` es falso: se elige `c`. | `mayor = 20`. |
| Menor | Solo `b < a Y b < c` es verdadero. | `a < b` es falso; `b < c` es verdadero: se elige `b`. | `menor = 8`. |
| Intermedio | `15 > 8 Y 15 < 20` es verdadero. | `a <> mayor Y a <> menor` es verdadero. | `intermedio = 15`. |
| Diferencia | Se restan los extremos. | Se restan los extremos. | `20 - 8 = 12`. |

`diferencia` se calcula después de encontrar los extremos. No es una suma acumulada: se asigna una sola vez y es positiva porque el mayor y el menor son diferentes.

## Equivalencias en C++

`Si` se expresa con `if`; `SiNo`, con `else`. `Y` se escribe `&&`, `O` se escribe `||`, la igualdad se compara con `==` y la desigualdad con `!=`. La asignación `<-` se convierte en `=`.

Se usa `long long` para los enteros. Como los datos válidos son positivos, restar el menor al mayor se mantiene dentro del rango del tipo.
