## ¿Qué es una transacción?

Una **transacción** es un conjunto de operaciones SQL que se ejecutan como una unidad atómica: o todas se completan con éxito mediante `COMMIT`, o ninguna tiene efecto mediante `ROLLBACK`. En MySQL se implementan dentro de procedimientos almacenados usando `START TRANSACTION`.

```sql
DELIMITER $$
CREATE PROCEDURE NOMBRE_PROC(IN param1 TIPO, IN param2 TIPO)
BEGIN
    DECLARE variable TIPO;
    SET AUTOCOMMIT = 0;
    START TRANSACTION;

    -- validaciones con IF EXISTS / IF NOT EXISTS
    -- operaciones INSERT / UPDATE / DELETE
    -- si algo falla:
    --   ROLLBACK;
    --   SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'ERROR';

    COMMIT;
END $$
DELIMITER ;

CALL NOMBRE_PROC(valor1, valor2);
```

## Conceptos clave

| Elemento | Para qué sirve |
| --- | --- |
| `SET AUTOCOMMIT = 0` | Desactiva la confirmación automática para controlar manualmente la transacción |
| `START TRANSACTION` | Marca el inicio del bloque transaccional |
| `COMMIT` | Confirma y persiste todos los cambios realizados en la transacción |
| `ROLLBACK` | Deshace todos los cambios si ocurre un error |
| `SIGNAL SQLSTATE '45000'` | Lanza un error personalizado con un mensaje descriptivo |
| `IF EXISTS(SELECT ...)` | Verifica que un registro ya existe antes de operar |
| `IF NOT EXISTS(SELECT ...)` | Verifica que un registro no existe, por ejemplo para evitar duplicados |
| `SELECT col INTO var` | Recupera un valor de la base de datos y lo guarda en una variable local |
| `INSERT INTO` | Inserta una nueva fila en una tabla |
| `UPDATE ... SET` | Modifica campos de filas existentes |
| `DELETE FROM` | Elimina físicamente una fila de una tabla |
| `MYSQL_ERRNO` | Código de error de MySQL; si es distinto de 0, ocurrió un fallo |

## Saldo en la base REPUESTOS

En esta base de datos no existe una tabla de depósito explícita. El saldo disponible de un repuesto se controla comparando la cantidad total comprada en `COMPRA` contra la cantidad total entregada en `ENTREGA` para el mismo repuesto y proveedor.

```text
            INGRESO                         EGRESO
               ↓                               ↓
           [ COMPRA ]  →→→  DEPOSITO  →→→  [ ENTREGA ]
                        CANTIDAD (+)      CANTIDADE (+)
                        SALDO    (+)      SALDO     (-)
```

## Ejercicio 1

<p class="border-l-4 border-brand bg-surface px-4 py-3 leading-relaxed">Registrar la compra de un repuesto a un proveedor y, al mismo tiempo, consignar la primera entrega correspondiente a esa compra. Los datos son el código del repuesto, el NIT del proveedor, la cantidad comprada, el costo y el ITEM del encargado de la entrega.</p>

<p><strong>Análisis:</strong> se valida que el repuesto, el proveedor y el encargado existan, y que la combinación <code>(CODIGO, NIT)</code> no tenga ya una compra registrada. Luego se inserta en <code>COMPRA</code> y se genera la entrega con el número máximo de entrega más uno.</p>

<Codigo archivo="transaccion-1.sql" lang="sql" plegado codigo={`USE REPUESTOS;
DELIMITER $$
CREATE PROCEDURE TRANSACCION1(IN CODI CHAR(6), IN NIP CHAR(10), IN CC INT, IN COSTO FLOAT, IN ITEN INT)
BEGIN
    DECLARE NE_NEW INT;
    SET AUTOCOMMIT = 0;
    START TRANSACTION;

    IF EXISTS(SELECT * FROM REPUESTO WHERE CODIGO = CODI) THEN
        IF EXISTS(SELECT * FROM PROVEEDOR WHERE NIT = NIP) THEN
            IF NOT EXISTS(SELECT * FROM COMPRA WHERE CODIGO = CODI AND NIT = NIP) THEN
                IF EXISTS(SELECT * FROM ENCARGADO WHERE ITEM = ITEN) THEN
                    BEGIN
                        INSERT INTO COMPRA VALUES (CODI, NIP, NOW(), CC, COSTO, 0.0, 0.0);
                        SET NE_NEW = (SELECT MAX(NE) + 1 FROM ENTREGA);
                        INSERT INTO ENTREGA VALUES (NE_NEW, NOW(), CC, CODI, NIP, ITEN);
                        IF (MYSQL_ERRNO <> 0) THEN
                            BEGIN
                                ROLLBACK;
                                SIGNAL SQLSTATE '45000'
                                SET MESSAGE_TEXT = 'TRANSACCIÓN NO COMPLETADA', MYSQL_ERRNO = '1006';
                            END;
                        END IF;
                    END;
                ELSE SELECT 'EL ENCARGADO NO ESTA REGISTRADO'; END IF;
            ELSE SELECT 'LA COMPRA YA FUE REGISTRADA PARA ESE PROVEEDOR'; END IF;
        ELSE SELECT 'EL PROVEEDOR NO ESTA REGISTRADO'; END IF;
    ELSE SELECT 'EL REPUESTO NO ESTA REGISTRADO'; END IF;

    COMMIT;
END $$
DELIMITER ;

CALL TRANSACCION1('R-0001', '1011112450', 10, 250.0, 10010);`} />

## Ejercicio 4

Si ya existe una compra de ese repuesto al mismo proveedor, se actualiza la cantidad acumulada; en caso contrario, se registra como nueva compra. Los datos son el código del repuesto, el NIT del proveedor, la cantidad y el costo unitario.</p>

<p><strong>Análisis:</strong> se verifican las existencias del repuesto y del proveedor. Luego se evalúa si ya existe el registro en <code>COMPRA</code>: de existir se incrementa la cantidad y, si no, se inserta uno nuevo.</p>

<Codigo archivo="transaccion-4.sql" lang="sql" plegado codigo={`USE REPUESTOS;
DELIMITER $$
CREATE PROCEDURE TRANSACCION4(IN CODI CHAR(6), IN NIP CHAR(10), IN CC INT, IN COSTO FLOAT)

    IF EXISTS(SELECT * FROM REPUESTO WHERE CODIGO = CODI) THEN

                END IF;
            END;

## Ejercicio 5

<p class="border-l-4 border-brand bg-surface px-4 py-3 leading-relaxed">Registrar una nueva entrega de un repuesto verificando que la cantidad total entregada hasta el momento no supere la cantidad total comprada. Si el saldo es suficiente, se registra la entrega; en caso contrario, se registra solo con la cantidad disponible. Los datos son el código del repuesto, el NIT del proveedor, la cantidad a entregar y el ITEM del encargado.</p>

<p><strong>Análisis:</strong> se calcula el saldo disponible restando el total ya entregado del total comprado. Según el resultado, se inserta la entrega con la cantidad solicitada, con el saldo real disponible o se muestra un mensaje de stock insuficiente.</p>

<Codigo archivo="transaccion-5.sql" lang="sql" plegado codigo={`USE REPUESTOS;
DELIMITER $$
CREATE PROCEDURE TRANSACCION5(IN CODI CHAR(6), IN NIP CHAR(10), IN CANTIDADE INT, IN ITEN INT)
BEGIN
    DECLARE TOTAL_COMP INT;
    DECLARE TOTAL_ENT  INT;
    DECLARE SALDO      INT;
    DECLARE NE_NEW     INT;

    SET AUTOCOMMIT = 0;
    START TRANSACTION;

    IF EXISTS(SELECT * FROM COMPRA WHERE CODIGO = CODI AND NIT = NIP) THEN
        IF EXISTS(SELECT * FROM ENCARGADO WHERE ITEM = ITEN) THEN
            BEGIN
                SELECT CANTIDAD INTO TOTAL_COMP FROM COMPRA WHERE CODIGO = CODI AND NIT = NIP;
                SELECT IFNULL(SUM(CANTIDADE), 0) INTO TOTAL_ENT FROM ENTREGA WHERE CODIGO = CODI AND NIT = NIP;
                SET SALDO = TOTAL_COMP - TOTAL_ENT;
                SET NE_NEW = (SELECT MAX(NE) + 1 FROM ENTREGA);

                IF (SALDO > 0) THEN
                    IF (SALDO >= CANTIDADE) THEN
                        INSERT INTO ENTREGA VALUES (NE_NEW, NOW(), CANTIDADE, CODI, NIP, ITEN);
                    ELSE
                        INSERT INTO ENTREGA VALUES (NE_NEW, NOW(), SALDO, CODI, NIP, ITEN);
                    END IF;
                ELSE
                    SELECT 'SIN STOCK DISPONIBLE PARA ESTE REPUESTO';
                END IF;

                IF (MYSQL_ERRNO <> 0) THEN
                    BEGIN
                        ROLLBACK;
                        SIGNAL SQLSTATE '45000'
                        SET MESSAGE_TEXT = 'TRANSACCIÓN NO COMPLETADA', MYSQL_ERRNO = '1006';
                    END;
                END IF;
            END;
        ELSE SELECT 'EL ENCARGADO NO ESTA REGISTRADO'; END IF;
    ELSE SELECT 'NO EXISTE COMPRA PARA ESE REPUESTO Y PROVEEDOR'; END IF;

    COMMIT;
END $$
DELIMITER ;

CALL TRANSACCION5('R-0001', '1011112450', 3, 10010);`} />

<p><strong>Nota:</strong> <code>IFNULL(SUM(...), 0)</code> evita que el cálculo devuelva <code>NULL</code> cuando todavía no hay entregas registradas para ese repuesto.</p>

## Ejercicio 6

<p class="border-l-4 border-brand bg-surface px-4 py-3 leading-relaxed">Eliminar físicamente el registro de una compra de un repuesto a un proveedor, eliminando también todas las entregas asociadas a esa compra. Los datos son el código del repuesto y el NIT del proveedor.</p>

<p><strong>Análisis:</strong> primero se eliminan las entregas porque tienen clave foránea hacia <code>COMPRA</code> y luego se elimina el registro de <code>COMPRA</code>. El orden es obligatorio para respetar la integridad referencial.</p>

<Codigo archivo="transaccion-6.sql" lang="sql" plegado codigo={`USE REPUESTOS;
DELIMITER $$
CREATE PROCEDURE TRANSACCION6(IN CODI CHAR(6), IN NIP CHAR(10))
BEGIN
    SET AUTOCOMMIT = 0;
    START TRANSACTION;

    IF EXISTS(SELECT * FROM COMPRA WHERE CODIGO = CODI AND NIT = NIP) THEN
        BEGIN
            DELETE FROM ENTREGA WHERE CODIGO = CODI AND NIT = NIP;
            DELETE FROM COMPRA  WHERE CODIGO = CODI AND NIT = NIP;
            IF (MYSQL_ERRNO <> 0) THEN
                BEGIN
                    ROLLBACK;
                    SIGNAL SQLSTATE '45000'
                    SET MESSAGE_TEXT = 'TRANSACCIÓN NO COMPLETADA', MYSQL_ERRNO = '1006';
                END;
            END IF;
        END;
    ELSE SELECT 'LA COMPRA NO EXISTE'; END IF;

    COMMIT;
END $$
DELIMITER ;

CALL TRANSACCION6('R-0001', '1011112450');`} />

<p><strong>Nota:</strong> siempre se deben eliminar primero los registros hijos (<code>ENTREGA</code>) antes que los registros padre (<code>COMPRA</code>), ya que existe una <code>FOREIGN KEY</code> que lo impone.</p>

## Ejercicio 7

<p class="border-l-4 border-brand bg-surface px-4 py-3 leading-relaxed">Actualizar la reducción de cantidad de una entrega existente. La cantidad de la compra correspondiente también deberá ajustarse para reflejar la devolución. Los datos son el número de entrega y la cantidad a disminuir.</p>

<p><strong>Análisis:</strong> se obtienen el código del repuesto y el NIT del proveedor desde la entrega. Se verifica que la disminución no deje la cantidad en negativo y, si es válido, se actualizan tanto <code>ENTREGA</code> como <code>COMPRA</code>.</p>

<Codigo archivo="transaccion-7.sql" lang="sql" plegado codigo={`USE REPUESTOS;
DELIMITER $$
CREATE PROCEDURE TRANSACCION7(IN NE_UPD INT, IN CDISM INT)
BEGIN
    DECLARE CODI    CHAR(6);
    DECLARE NIP     CHAR(10);
    DECLARE CANTE   INT;

    SET AUTOCOMMIT = 0;
    START TRANSACTION;

    IF EXISTS(SELECT * FROM ENTREGA WHERE NE = NE_UPD) THEN
        BEGIN
            SELECT CODIGO, NIT, CANTIDADE INTO CODI, NIP, CANTE FROM ENTREGA WHERE NE = NE_UPD;

            IF (CANTE >= CDISM) THEN
                BEGIN
                    UPDATE ENTREGA SET CANTIDADE = CANTIDADE - CDISM WHERE NE = NE_UPD;
                    UPDATE COMPRA  SET CANTIDAD  = CANTIDAD  - CDISM WHERE CODIGO = CODI AND NIT = NIP;
                    IF (MYSQL_ERRNO <> 0) THEN
                        BEGIN
                            ROLLBACK;
                            SIGNAL SQLSTATE '45000'
                            SET MESSAGE_TEXT = 'TRANSACCIÓN NO COMPLETADA', MYSQL_ERRNO = '1006';
                        END;
                    END IF;
                END;
            ELSE SELECT 'LA CANTIDAD A DISMINUIR SUPERA LA CANTIDAD REGISTRADA EN LA ENTREGA'; END IF;
        END;
    ELSE SELECT 'LA ENTREGA NO EXISTE'; END IF;

    COMMIT;
END $$
DELIMITER ;

CALL TRANSACCION7(102, 1);`} />

## Ejercicios propuestos

Resuelve las siguientes transacciones como práctica. No se incluye la resolución para que puedas plantear las validaciones y el orden de las operaciones.

1. **T8.** Registrar simultáneamente una compra y su primera entrega, y además verificar si el repuesto es de tipo `ELECTRICO` o `MECANICO` para registrar el dato correspondiente en la tabla respectiva si aún no existe. Los datos son: código del repuesto, NIT del proveedor, cantidad, costo, ITEM del encargado, tipo de repuesto (`'E'` o `'M'`) y el dato específico (potencia o especificación).
2. **T9.** Registrar una entrega de un repuesto por parte de un encargado de una ciudad determinada. Si el encargado ya tiene una entrega registrada para el mismo repuesto y proveedor, se actualiza la cantidad; caso contrario, se registra una nueva entrega. Los datos son: el nombre del encargado, la ciudad, el código del repuesto y el NIT del proveedor.
3. **T10.** Eliminar el registro de una compra de materiales de un proveedor determinado, actualizando también las entregas de modo que se eliminen todas las entregas cuya cantidad supere el saldo disponible luego de la eliminación. Los datos son: el código del repuesto y el NIT del proveedor.
4. **T11.** Transferir todas las entregas asignadas a un encargado hacia otro encargado registrado en la base de datos. Se debe verificar que ambos encargados existan. Los datos son: el ITEM del encargado origen y el ITEM del encargado destino.

## Checklist de revisión

- Iniciar la transacción con `START TRANSACTION` y cerrarla con `COMMIT`.
- Usar `ROLLBACK` cuando una operación falle o una validación no se cumpla.
- Validar la existencia del repuesto, proveedor, encargado y compra antes de operar.
- Respetar el orden de eliminación que imponen las claves foráneas.
- Calcular el saldo antes de registrar una entrega.
- Comprobar el resultado con `SELECT` después de ejecutar el procedimiento.
