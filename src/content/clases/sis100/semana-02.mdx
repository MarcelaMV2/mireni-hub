## Ejercicio 1 · Análisis de tres números

<Enunciado>
Desarrolle un algoritmo que permita analizar tres números enteros positivos
diferentes ingresados por teclado.

Los valores ingresados deben ser validados, considerando que deben cumplir con
las condiciones establecidas: ser positivos y no repetirse entre ellos.

Una vez ingresados y validados los datos, el algoritmo debe determinar cuál de
los valores corresponde al número mayor, cuál al número menor y cuál al número
intermedio.

Finalmente, calcular y mostrar la diferencia existente entre el número mayor y
el número menor.
</Enunciado>

### Mostrar:

- Número mayor.
- Número intermedio.
- Número menor.
- Diferencia entre mayor y menor.

El ejercicio debe ser resuelto mediante dos versiones del algoritmo:

1. Una versión utilizando únicamente **estructuras selectivas simples**.
2. Una versión utilizando **estructuras selectivas dobles**.

### Ejemplos de funcionamiento

| Caso | Datos de entrada | Datos de salida / respuesta del programa |
| --- | --- | --- |
| Valores desordenados | `a = 15`, `b = 8`, `c = 20` | Mayor: `20`. Intermedio: `15`. Menor: `8`. Diferencia: `12`. |
| Orden ascendente | `a = 3`, `b = 7`, `c = 12` | Mayor: `12`. Intermedio: `7`. Menor: `3`. Diferencia: `9`. |
| Orden descendente | `a = 30`, `b = 20`, `c = 10` | Mayor: `30`. Intermedio: `20`. Menor: `10`. Diferencia: `20`. |
| Cero | `a = 0`, `b = 8`, `c = 20` | Se rechaza el proceso: los números deben ser positivos. |
| Negativo | `a = 15`, `b = -8`, `c = 20` | Se rechaza el proceso: los números deben ser positivos. |
| Dos iguales | `a = 15`, `b = 8`, `c = 15` | Se rechaza el proceso: los números deben ser diferentes. |
| Tres iguales | `a = 5`, `b = 5`, `c = 5` | Se rechaza el proceso: los números deben ser diferentes. |

## Ejercicio 2 · Facturación con descuento

<Enunciado>
Desarrolle un algoritmo que permita calcular el monto final de una compra
realizada en una tienda.

El algoritmo debe calcular el valor total de una compra considerando el precio
unitario de un producto y la cantidad de unidades adquiridas. Los valores
utilizados para realizar los cálculos deben ser validados, considerando que el
precio y la cantidad deben tener valores positivos.

Antes de desarrollar el algoritmo, establezca un monto límite de compra y un
porcentaje de descuento que será aplicado. Si el monto total de la compra supera
el límite establecido, se deberá aplicar el descuento correspondiente; caso
contrario, la compra mantendrá su valor sin descuento.

El programa debe calcular el monto total de la compra, determinar si corresponde
aplicar el descuento y obtener el monto final que deberá pagar el cliente.

Finalmente, mostrar la información relacionada con la compra realizada:
</Enunciado>

- Precio unitario.
- Cantidad comprada.
- Monto total de la compra.
- Descuento aplicado.
- Monto final a pagar.

El ejercicio debe ser resuelto mediante dos versiones del algoritmo:

1. Una versión utilizando únicamente **estructuras selectivas simples**.
2. Una versión utilizando **estructuras selectivas dobles**.

### Ejemplos de funcionamiento

| Caso | Datos de entrada | Datos de salida / respuesta del programa |
| --- | --- | --- |
| Con descuento | `precio = 50`, `cantidad = 4`, `limite = 150`, `porcentaje = 10` | Precio: `50`. Cantidad: `4`. Total: `200`. Descuento: `20`. Final: `180`. |
| Total igual al límite | `precio = 50`, `cantidad = 3`, `limite = 150`, `porcentaje = 10` | Precio: `50`. Cantidad: `3`. Total: `150`. Descuento: `0`. Final: `150`. |
| Total menor al límite | `precio = 50`, `cantidad = 2`, `limite = 150`, `porcentaje = 10` | Precio: `50`. Cantidad: `2`. Total: `100`. Descuento: `0`. Final: `100`. |
| Precio inválido | `precio = 0`, `cantidad = 4`, `limite = 150`, `porcentaje = 10` | Se rechaza el proceso: el precio debe ser positivo. |
| Cantidad inválida | `precio = 50`, `cantidad = -2`, `limite = 150`, `porcentaje = 10` | Se rechaza el proceso: la cantidad debe ser positiva. |
| Límite inválido | `precio = 50`, `cantidad = 4`, `limite = 0`, `porcentaje = 10` | Se rechaza el proceso: el límite debe ser positivo. |
| Porcentaje inválido | `precio = 50`, `cantidad = 4`, `limite = 150`, `porcentaje = 0` | Se rechaza el proceso: el porcentaje debe ser positivo. |

Los motivos de rechazo se muestran por separado en la versión simple; la doble muestra el mensaje general «Los datos deben ser positivos».
