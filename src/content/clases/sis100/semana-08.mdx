## ¿Qué es la modularidad?

La **programación modular** consiste en dividir un problema grande en partes más pequeñas llamadas **módulos**. Cada módulo se encarga de una tarea específica y el programa principal coordina el trabajo de todos ellos.

Un módulo puede recibir datos, procesarlos y devolver un resultado. Por ejemplo, un programa puede tener un módulo para leer datos, otro para calcular una suma y otro para mostrar los resultados.

### Conceptos básicos de programación modular

| Concepto | Descripción | Ejemplo |
| --- | --- | --- |
| **Programación modular** | Técnica que divide un problema en partes pequeñas llamadas **módulos** o subalgoritmos, donde cada uno realiza una tarea específica y el algoritmo principal coordina su ejecución. | — |
| **Subalgoritmo** | Parte del programa que realiza una función determinada. Puede recibir datos, procesarlos y devolver un resultado o mostrar información. | — |
| **Función Tipo A** | Subalgoritmo que devuelve un valor mediante un resultado. | `resultado ← CalcularSuma(a,b)` |
| **Función Tipo B** | Subalgoritmo que no devuelve valores, solo realiza una acción como mostrar información. | `MostrarResultado()` |
| **Algoritmo principal** | Módulo encargado de organizar el programa, llamar a las funciones y controlar el proceso general. | — |
| **Ordinograma** | Representación gráfica de un algoritmo mediante símbolos que muestran la secuencia de pasos. | — |
| **Variable local** | Variable creada dentro de un módulo y solo puede utilizarse dentro de él. | — |
| **Variable global** | Variable declarada en el algoritmo principal y puede ser utilizada por diferentes módulos. | — |

### ¿Por qué dividir el programa?

La modularidad permite:

- Entender el problema por partes.
- Escribir y revisar cada tarea de manera independiente.
- Reutilizar un módulo en otros programas.
- Encontrar errores con mayor facilidad.
- Evitar que el programa principal se vuelva demasiado extenso.

Cada módulo debe tener una **responsabilidad clara**. Si un módulo genera un número, su trabajo es generar el número; si otro separa sus dígitos, no debería encargarse también de comprobar si es primo.

### Programa principal y módulos

El **programa principal** organiza el orden general del algoritmo. Los módulos realizan las tareas concretas cuando el programa principal los llama.

```text
Algoritmo Principal
    dato <- ModuloLeerDato()
    resultado <- ModuloProcesar(dato)
    ModuloMostrar(resultado)
FinAlgoritmo
```

La idea es que cada módulo pueda entenderse por separado y que sus nombres indiquen claramente qué tarea realiza. En PSeInt, los módulos pueden escribirse como `SubProceso` o `Funcion`, según necesiten devolver un resultado.

## Ejercicio 1 · Ordenamiento y comparación de un número de tres dígitos

<Enunciado>
Desarrolle un algoritmo aplicando programación modular que permita ingresar un número entero positivo de tres dígitos.

El algoritmo debe:

- Verificar que el número ingresado corresponda a un valor de tres dígitos.
- Separar los dígitos que conforman el número.
- Formar un nuevo número ordenando sus dígitos de mayor a menor.
- Calcular la diferencia entre el número ordenado y el número original.
- Mostrar el número ingresado, el número formado con los dígitos ordenados y el resultado obtenido.

Además, deberá indicar mediante un mensaje la situación correspondiente:

- Si la diferencia es igual a cero, indicar que ambos números son iguales.
- Si la diferencia es mayor a cero, indicar que el número ordenado es mayor al número ingresado.

El algoritmo debe desarrollarse utilizando únicamente tres funciones, aplicando funciones de tipo A y tipo B, y el algoritmo principal debe realizar la llamada a dichas funciones.
</Enunciado>

### Ejemplos de funcionamiento

| Caso | Datos de entrada | Datos de salida / respuesta del programa |
| --- | --- | --- |
| Dígitos distintos | Número: `582` | Número ingresado: `582`. Número ordenado: `852`. Diferencia: `270`. El número ordenado es mayor al número ingresado. |
| Dígitos repetidos | Número: `777` | Número ingresado: `777`. Número ordenado: `777`. Diferencia: `0`. Los números son iguales. |

## Ejercicio 2 · Número aleatorio de tres dígitos

<Enunciado>
Desarrolle un algoritmo aplicando programación modular que genere aleatoriamente un número entero positivo de tres dígitos comprendido entre `100` y `999`.

El algoritmo debe analizar el número generado mediante los siguientes procesos:

- Separar los dígitos que conforman el número.
- Calcular la suma de sus dígitos.
- Determinar si el número generado es primo o no.

Finalmente, deberá presentar todos los resultados obtenidos desde el algoritmo principal.

El algoritmo debe desarrollarse utilizando tres funciones, aplicando funciones de tipo A y tipo B, donde el algoritmo principal deberá realizar la llamada a dichas funciones.
</Enunciado>

### Ejemplos de funcionamiento

| Caso | Datos de entrada | Datos de salida / respuesta del programa |
| --- | --- | --- |
| Número primo | Número generado: `137` | Dígitos: `1 3 7`. Suma de los dígitos: `11`. ¿El número es primo?: Sí. |
| Número no primo | Número generado: `142` | Dígitos: `1 4 2`. Suma de los dígitos: `7`. ¿El número es primo?: No. |
